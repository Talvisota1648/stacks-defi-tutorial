# ОСЦ — MVP 2.0

Камеры → локальная модель → материалы события → проверка специалистом → API ситуационного центра.
Пилот ограничен **10 источниками**. Обязательных платных API нет.

## Обновление для презентации

Добавлены вход по логину/паролю, последние 10 кадров камер, галерея материалов и ручной анализ
через локальный YOLOX или OpenRouter. Камеры, ключи и доступ демонстратора настраиваются через сайт.
[Пошаговая инструкция для RunPod и демонстратора](docs/PRESENTATION.md).

```bash
cd /workspace/stacks-defi-tutorial
git pull origin starter-code
bash scripts/runpod-update.sh
```

Это обновление выполняет оператор один раз. После него демонстратор открывает HTTPS-ссылку
сервиса RunPod на порту 3000 и вводит выданные логин/пароль; ему не нужны SSH и команды.

## Быстрый запуск на своём компьютере / VPS

Нужны Docker с Compose и Node.js для генерации настроек. На Windows — Docker Desktop с WSL2.
Python, FFmpeg и модель будут внутри контейнеров. Запускайте из корня репозитория:

```sh
git pull origin starter-code
node scripts/init-env.cjs
node scripts/presentation-access.cjs
docker compose up -d --build
```

Если проект скачан ZIP-архивом, пропустите `git pull`. Существующий `.env` генератор не перезаписывает.
Первый запуск скачивает зависимости и небольшой файл модели YOLOX Nano с проверкой SHA-256.
После этого анализ работает локально, без подключения к сервису ИИ.

Откройте **http://localhost:3000**. Для администратора раскройте «Вход по токену» и вставьте `OSC_ADMIN_TOKEN`
из корневого `.env`. Для демонстратора используется обычный логин/пароль. Для администратора есть расширенный вход по токену; сессия хранится в HttpOnly cookie. Не отправляйте `.env` в чат или Git.
Проверьте, что на экране появился хотя бы один активный локальный обработчик.

### Подключить RTSP-камеру

На сайте войдите администратором → «Добавить источник» → RTSP → вставьте адрес
`rtsp://USER:PASSWORD@CAMERA_HOST:554/STREAM` в поле «RTSP-ссылка». Ссылка хранится
зашифрованной; перезапуск не нужен. Используйте свои или разрешённые владельцем потоки.
После первого кадра настройте зону. На карточке доступны последний кадр и история десяти кадров.
«Настроить зону» также позволяет изменить подключение; кнопка «Переподключить» перезапускает
только этот поток. Старые CAMERA_01_URL-переменные поддерживаются как запасной способ.

Нужен RTSP over TCP, предпочтительно H.264 и GOP до 2 секунд. ONVIF-поиск не реализован.
Камеры за NAT должны быть доступны серверу через вашу сеть/VPN.

### Мобильный комплекс / проба на видеофайле

Создайте источник «Загрузка файлов комплекса», загрузите MP4 до 250 МБ и 120 секунд.
После первого клипа настройте зону и повторно загрузите тот же файл: изменение правила разрешает
повторный анализ. Повторная загрузка тех же байтов с той же конфигурацией не создаёт дубликат.
Для автоматической передачи используйте upload API с отдельным ingest-токеном.
Зоны координат кадра применимы к неподвижному ракурсу: движущуюся камеру с меняющейся геометрией
нельзя использовать как стационарный контроль парковки без дополнительной стабилизации/геопривязки.

### Проверка и интеграция

Выберите событие, просмотрите кадр, клип и предшествующие клипы, внесите заключение и утвердите
или отклоните. **Только утверждённые события** доступны в `GET /integration/v1/events`.
Проверяющему выдайте `OSC_REVIEWER_TOKEN`, комплексу — `OSC_INGEST_TOKEN`, центру —
`OSC_INTEGRATION_TOKEN`. Администратор может менять камеры и правила; интегратор — нет.

OpenAPI: **http://localhost:8000/docs**. [Архитектура, API и ограничения](docs/MVP2.md).
Порты по умолчанию привязаны только к loopback. Для удалённого сайта поставьте HTTPS reverse proxy.

```sh
docker compose logs --tail=100 api collector worker
docker compose down
```

Не добавляйте `-v` при обычной остановке: этот флаг удалит БД, модель и материалы.
Входящие файлы без событий удаляются после заданного срока (для новых установок — 1 час); материалы событий и связанный контекст
автоматически не удаляются. Планируйте место, архив и резервные копии. При заполнении диска/очереди
сбор останавливается с ошибкой, а не объявляется успешно обработанным.

## Минимальный запуск без Docker (CPU)

Нужны **Python 3.12, FFmpeg в PATH и Node.js 24**. В отличие от MVP 1, одного Node.js уже недостаточно.
Из `backend`:

```sh
python -m venv .venv
# Windows CMD:
.venv\Scripts\activate
# Linux/macOS вместо предыдущей строки: source .venv/bin/activate
pip install -r requirements.txt
python -m osc.init_config
python -m osc.download_model
python -m osc.run api
```

В двух новых консолях из `backend` с активированным venv:

```sh
python -m osc.run worker
```

```sh
python -m osc.run collector
```

В отдельной консоли из `frontend`:

```sh
npm ci
npm run dev
```

В этом режиме используется SQLite для одного сервера. Токены/адреса читаются из корневого `.env`.
После их изменения перезапустите соответствующие процессы. `/manual` позволяет анализировать отдельные фото/видео локально либо через OpenRouter.
Ключ и модель меняются администратором в настройках сайта без перезапуска.

## Проверки

```sh
# backend, с активированным venv:
python -m pytest -q
# frontend:
npm test
npm run build
```

Тест реального детектора требует скачанной модели и файла изображения автобуса:
`OSC_TEST_IMAGE=/path/to/bus.jpg python -m pytest -m model -q` (на Windows задайте переменную через `set`).
Без этих файлов данный тест явно пропускается; остальные проверки не подменяют качество модели.
