# Презентация: обычная HTTPS-ссылка, без SSH у демонстратора

## Однократное обновление существующего RunPod

В уже открытом SSH-терминале оператора (не на компьютере демонстратора):

```bash
cd /workspace/stacks-defi-tutorial
git pull origin starter-code
bash scripts/runpod-update.sh
```

Скрипт использует `/workspace/miniforge3/envs/osc`, устанавливает зависимости, проверяет модель,
собирает сайт и заменяет только процессы этого приложения. Существующие `.env`, камеры, события
и материалы сохраняются. В БД добавляются новые таблицы; старые таблицы не удаляются.
Не удаляйте `.env`: от серверного ключа зависит расшифровка настроек.
Если `git pull` сообщает о локальных изменениях, сначала разберите их; не делайте принудительный reset.

Скрипт создаёт логин для презентации, только если он ещё не настроен; значения находятся в корневом
`.env` и не печатаются в журнал. Веб-сайт слушает `0.0.0.0:3000`, backend — только `127.0.0.1:8000`.

В настройках RunPod должен быть выставлен **HTTP port 3000**. В Connect откройте появившуюся
HTTPS-ссылку этого сервиса. Не используйте `localhost` на чужом компьютере и не передавайте SSH-ключи.
Если изменение портов перезапустило Pod, запустите приложение снова (см. ниже).

## Что подготовить организатору

1. Открыть HTTPS-ссылку RunPod, войти как администратор через «Вход по токену» на главной странице.
   Используется существующий `OSC_ADMIN_TOKEN` из корневого `.env`.
2. «Настройки OpenRouter» → «Доступ для презентации»: задать удобный логин и пароль не короче
   12 символов. Пароль не выводится обратно; смена пароля завершает старые сессии демонстратора.
3. При использовании внешней модели сохранить ключ и имя модели. По умолчанию задано
   `google/gemini-3.8-flash`, но сохранённые ранее настройки/OPENROUTER_MODEL не перезаписываются.
   Есть бесплатная по отношению к анализу проверка ключа через `/api/v1/key`; она не подтверждает,
   что выбранная модель доступна и что её качество достаточно. Проверьте один реальный анализ заранее.
4. Добавить камеру, вставив RTSP-ссылку прямо в форму. Адрес и пароль сохраняются зашифрованными,
   не возвращаются в API и не попадают в аудит. Старый режим CAMERA_01_URL также поддерживается.
5. При изменении адреса камера переподключается автоматически (обычно в пределах 15–30 секунд).
   Кнопка «Переподключить» перезапускает только подключение этой камеры, не весь Pod.
6. Проверить первый кадр и при необходимости настроить зону. Для демонстрации подготовить
   собственные/разрешённые файлы и реальные проверенные материалы; не выдавать тестовые данные за находки.

Передать демонстратору **только HTTPS-ссылку, логин и пароль**. Проверить доступ именно с компьютера
и из сети будущей презентации: корпоративная сеть может ограничивать внешние домены.
Демонстратор не получает токен администратора, SSH, ключ OpenRouter и права менять камеры/ключи.

## Что доступно в браузере

- Главная: кадр каждой камеры, последние 10 обработанных кадров с временем МСК, увеличение изображения.
  Это выборка обработанных кадров, а не живое видео. Свежесть оценивается по времени, не по наличию картинки.
- Происшествия: отдельные сохранённые кадры, видео, предшествующие клипы, комментарий и решение специалиста.
  Эти файлы не перезаписываются при ротации десяти кадров камеры.
- «Фото и видео»: выбор локальной модели или OpenRouter, загрузка одного файла, история и JSON-отчёт.
  Фото JPG/PNG/WebP до 20 МБ/40 МП; видео MP4/MOV/WebM/AVI до 250 МБ и 120 секунд.
- Локальная модель: реальные рамки людей и транспорта на изображениях. Наличие объекта — не нарушение;
  OCR номеров, свалки и незаконность строений локальным YOLOX не определяются.
- OpenRouter: один запрос на фото/выборку до 12 изображений. Необязательная вырезка номера в исходном
  разрешении. Прочтения по каждому кадру, проверка российского формата и варианты при расхождениях.
  Повторные ответы одной модели не являются независимым подтверждением правильности.
- Ручной отчёт не утверждает нарушение автоматически и не отправляется в интеграционную ленту.
  Прежний неавторизованный `/api/analyze` отключён (410), чтобы нельзя было расходовать ключ в обход входа.

Настройки подхватываются без перезапуска worker: каждый новый анализ читает актуальный ключ/модель.
Уже выполняющийся запрос завершится с теми настройками, с которыми он был начат.

## Хранение и доступ

Последние 10 кадров камеры ограничены десятью JPEG-файлами на источник. Кадры/клипы происшествий
сохраняются отдельно. История ручных анализов хранит исходные файлы и подготовленные изображения;
автоматической очистки ручных отчётов пока нет. Следите за свободным местом; очередь имеет ограничения.
Материалы доступны только вошедшим пользователям, интегратору — лишь утверждённые события.

Ключ провайдера, RTSP и пароль презентации шифруются Fernet. Для шифрования используется
`OSC_SETTINGS_KEY` (если задан), иначе ключ выводится из `OSC_ADMIN_TOKEN`. Для восстановления нужны
резервные копии БД, каталога данных и стабильного серверного ключа. При его замене требуется миграция
зашифрованных настроек, а не простая регенерация `.env`.

Сессия — подписанная HttpOnly/SameSite cookie на 8 часов; HTTPS-прокси должен сохранять forwarded
host/proto. Для публичного развёртывания используйте HTTPS. Один демонстрационный аккаунт не заменяет
корпоративный SSO, индивидуальные роли и промышленную политику хранения.

## Управление после установки

```bash
source /workspace/miniforge3/etc/profile.d/conda.sh
conda activate osc
cd /workspace/stacks-defi-tutorial/backend
python -m osc.control status
python -m osc.control restart --public
```

После выключения/перезапуска Pod процессы нужно запустить: `python -m osc.control start --public`.
Сам контроллер не меняет стартовую команду RunPod и не обещает запуск после перезагрузки платформы.
Для остановки: `python -m osc.control stop`. Логи: `logs/api.log`, `worker.log`, `collector.log`, `web.log`.
Камеры и ключи повседневно меняются через сайт — эти команды нужны только оператору для обслуживания.

## Проверено здесь и что осталось проверить на RunPod

В среде разработки проверены: локальные фото и видео на CPU, сохранение истории/кадров, 10-кадровое
кольцо, галерея происшествий, вход по паролю и токену, смена доступа, CSRF/права, динамические настройки,
запуск/статус/остановка четырёх процессов, production-сборка и мобильный браузер.
OpenRouter покрыт тестом с подменённым ответом; платный запрос с ключом заказчика не выполнялся.
`google/gemini-3.8-flash` присутствует в публичном каталоге на момент проверки, но доступ конкретного ключа
проверяется отдельно. Реальное обновление RunPod и внешняя HTTPS-ссылка ещё требуют проверки оператором:
из этой среды нет доступа к SSH-ключу его компьютера.

## Если RunPod предупреждает, что изменение портов удалит данные

Не сохраняйте Edit Pod без проверки дисков/резервной копии. Можно использовать уже открытый
HTTP-порт 8888, если он свободен и Jupyter на нём не работает. Проверьте `ss -ltnp`.
Сохраните `OSC_WEB_PORT=8888` в корневом `.env`, затем из backend выполните
`python -m osc.control restart --replace --public`. В Connect откройте существующую HTTPS-ссылку
сервиса 8888 (название Jupyter Notebook может остаться прежним). Ничего менять в Edit Pod не нужно.
Не останавливайте чужой сервис на 8888 ради такого переключения: этот способ только для свободного порта.
Контроллер проверяет занятость выбранного порта до запуска и распознаёт запуск Next через conda `.bin/next`.

### Результаты обработки камер

В разделе «Результаты обработки» нажмите «Посмотреть» у нужного клипа
или «Результаты» на карточке камеры. Отчёт содержит модель, частоту,
число проверенных кадров, сводку объектов и до 12 кадров с рамками,
временем и оценками детектора. Объекты видны даже при отсутствии сигналов.
Максимум объектов в одном кадре не является числом уникальных людей или машин.
Старые клипы, обработанные до этого обновления, подробного отчёта не имеют.
Отчёты клипов без событий хранятся вместе с клипами (по умолчанию 24 часа);
материалы событий сохраняются. Галерея последних 10 кадров — отдельная функция.

Администратор меняет частоту (0,2–5 кадров/с) через «Настройки камеры».
Новое значение применяется к следующим заданиям без перезапуска.
Меню «···» на карточке позволяет переподключить, выключить или удалить камеру.
Удаление отключает сбор и освобождает место в лимите 10 источников;
история событий, отчёты и доказательства остаются с прежними сроками хранения.

### Аварийные ситуации и редактируемые сценарии

В «Настройки → Сценарии и запрещённые объекты» включаются базовые сценарии,
дополнительный текст критериев и список объектов (по одному в строке).
Для пользовательских критериев включите «Дополнительный сценарий администратора»,
для списка объектов — «Заданные администратором запрещённые объекты».
Изменения действуют на следующие анализы без перезапуска. В отчёте сохраняются
использованные критерии; прежние отчёты не переписываются.

Включены сценарии повреждённых/перевёрнутых машин, признаков ДТП, препятствий,
опасного положения на дороге/обочине, разметки, парковки, светофоров и манёвров,
людей на дороге, пожара/дыма, разливов, подтопления, люков и дорожного покрытия,
повреждённой инфраструктуры, мусора, строительных работ, самокатов,
животных, видимого конфликта и вандализма. Это перечень проверяемых признаков,
а не гарантия обнаружения любой ситуации. По одному фото нельзя установить
скорость, пересечение линии, длительность стоянки или законность строения.
Обычная перевозка разбитой машины эвакуатором не является отдельным сигналом.

Для фото/видео выберите OpenRouter. Сигналы отмечаются красными рамками,
если модель смогла указать область; описание без координат остаётся текстовым.
Локальный YOLOX Nano по-прежнему распознаёт только объекты. Для локального
анализа аварий можно подключить отдельный OpenAI-совместимый vision-сервер:
например, установить Ollama, загрузить vision-модель, указать API
`http://127.0.0.1:11434/v1` и имя `qwen2.5vl:7b`, затем включить дополнение
локального анализа. Приложение само не устанавливает эту модель.
Нужное оборудование и скорость зависят от выбранной модели; CPU 2 ядра/4 ГБ
не являются достаточным оборудованием для такой vision-модели.

Автоматическая проверка камер по умолчанию выключена. Администратор включает
её явно, выбирает OpenRouter либо локальный vision-сервер, интервал 10–3600 с
(по умолчанию 60 с) и 1–4 кадра на запрос (по умолчанию 2).
OpenRouter расходует баланс ключа. Не более одного запроса на камеру за
интервал при нормальной работе; таймаут провайдера не повторяется внутри запроса.
Похожие сигналы одной категории в одной области подавляются на 5 минут.
Одинаковая область не гарантирует один и тот же объект — специалист проверяет
кадр и контекст. Частота запросов и частота YOLOX — отдельные настройки.

Проверка сцены выполняется даже при отсутствии объектов YOLOX: повреждённая
машина может быть пропущена обычным детектором. Сигнал сохраняет кадр,
исходный клип, модель и описание в очереди специалиста; интеграция получает
его только после утверждения. При ошибке vision-модели отчёт явно сообщает,
что проверка сцены не выполнена; отсутствие сигналов не означает отсутствие риска.
Без включения проверки сцен отчёт об объектах не является проверкой нарушений.
